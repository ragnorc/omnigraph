## Lessons from earlier runs

The run on 2026-11-06 was the only earlier run. Its report listed these gaps: embeddings, faults below the object store, scale (deep history and many branches), and MCP. This run spent most of its time on those gaps. It also spent time on the 16 commits that landed after the earlier run: column-patch updates (#1272), fragment-scoped merges (#1229), required and `@unique` promotion (#1271), the handle-cache eviction (#1276), the null split (#1286) and the update admission charge (#1304).

The earlier run had two kinds of false alarm, and this run avoided both:

- `nearest` order differed by about 1e-7, because the harness computed distances in f64 and Lance uses f32. This run uses vector values that f32 holds exactly.
- A merge load or keyed insert that omits a property erases it (#1278, still open). The new fuzzers supply every property in each load.

## Issues filed and commented

| Issue | Finding | Severity |
|---|---|---|
| [#1305](https://github.com/ModernRelay/omnigraph/issues/1305) | A body-level `@unique(p)` on a list or vector property passes `init`, `lint`, `schema plan` and `cluster validate`. Every write that sets the property then fails with a raw `scalar key: unsupported column type` error. The constraint cannot be removed, so a rebuild is the only fix. The property-level shorthand is refused at parse time. | Medium |
| [#644](https://github.com/ModernRelay/omnigraph/issues/644) (comment) | `cleanup` still does not reclaim `__manifest` data. Each single-row commit writes a new 78 to 180 KB file. 1,500 commits left 168.6 MB that `cleanup --keep 100` did not touch. With 3,013 commits and 80 live branches, cleanup took 261 s. | Already open |

The GQT case for #1305 is [tools/stress/repros/issue_1305_unique_on_list.gqt](../../tools/stress/repros/issue_1305_unique_on_list.gqt). It fails on the base commit.

Two further findings are security issues under [SECURITY.md](../../SECURITY.md). They went to the maintainers as private security advisories, so this public report does not describe them. Their details will be public when the advisories are published.

## Journeys

Each journey used the built CLI and server as a user would. The run compared each result with the docs and, where possible, with an oracle.

| Journey | Result |
|---|---|
| Schema promotion: required and `@unique` on String, I64, list, Blob, vector, enum, F64 and edge properties, with conflicts held only by deleted rows or older row versions | Pass, except #1305. Deleted rows and earlier versions did not count. `0.0` and `-0.0` count as one `@unique` value. |
| Column-patch updates of scalar, list, Blob and vector properties, on main and on branches, with merges, `optimize` and `index build` | Pass. Blob bytes and vectors stayed exact in every export. |
| Change feed after column patches on a row with a Blob and a vector | Pass. Before and after images were exact. |
| Update admission on a fragment with 54 MB of Blob payload | Pass. One-row and three-row updates were admitted. Ten matched rows (45,000,000 bytes) were refused with a typed resource limit. |
| Embeddings with the `mock` provider: `embed` fill, `--reembed-all`, refusal of a non-string source, load, text `nearest` before and after `index build`, and the model guard | Pass. Vectors were deterministic and L2-normalized. A record whose text equals the query ranked first at distance 0. A trailing space changed the vector, as the docs say. |
| Deep history: 3,000 commits, `optimize` every 250, reads at 60 historical commits, `commit list`, `diff`, 80 branches created from historical commits, 32 merges, `cleanup --keep 100` | Pass. Reads at retained commits were unchanged after cleanup. 36 of 40 sampled reclaimed commits refused, and none returned wrong rows. See the #644 comment for storage. |
| Write latency against history | Flat. With the same rows, 80 branches or 1,500 commits changed nothing (0.071 to 0.074 s). The 3,000-commit graph, with merges, compactions and 347 MB of `__manifest` data, wrote in 0.159 s, against 0.084 s for a fresh graph. |
| Serve with bearer tokens and a three-rule policy: queries, mutations, branches, merges, export | Pass |
| MCP: tool listing and annotations, reads, conditional writes, branches, `load`, the 64 KiB and concurrency limits, Host, Origin and token refusals, resources | Pass except the two rows in the table above and one private advisory |
