## Lessons from earlier runs

The runs on 2026-11-06 and 2026-11-08 listed these gaps: RustFS and toxiproxy (no Docker), cleanup during long reads, the `omnigraph mcp` stdio bridge, an upgrade from the previous release, and real embedding providers. This run downloaded the RustFS and toxiproxy binaries instead of using Docker, and spent most of its time on storage faults and on the 26 commits merged since the last run. The most important of those commits are the unfiltered limit pushed to Lance (#1342), bounded and served `optimize` (#1275, #1282), denied reads on graphs without a policy, the MCP allocation and query-nesting fixes, the dataset cache and OCC validation change (#1291), and merge deletes by `_rowid` (#1301).

The earlier runs had three kinds of false alarm. This run avoided them:

- Vector distances: the fuzzers use values that f32 holds exactly.
- A merge load that omits a property erases it (#1278, still open): every load supplies every property.
- Documented refusals under concurrent writes (`409 read_set_conflict`, optimize refused under writes): the harness counts them as refusals, not failures.

Cleanup during long reads (#958) is a known open issue, so the run did not test it again. Real embedding providers stay a gap, because the box has no provider key in scope.

## Issues filed

The guide lists 409 only for conflicts that need a new request, so a scheduler does not retry. `refusal()` in `recorded_operations.rs` maps every cluster diagnostic to a conflict. | Low |

The reproductions are [tools/stress/repros/export_blocks_branch_control.py](../../tools/stress/repros/export_blocks_branch_control.py) and [tools/stress/repros/optimize_state_read_409.py](../../tools/stress/repros/optimize_state_read_409.py). Both fail on the base commit and on `108714a4`.
