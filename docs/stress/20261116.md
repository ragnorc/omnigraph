## Lessons from earlier runs

The findings queue (graph `beads`) was new for this run and held no memories, so the lessons come from the summaries of the three earlier runs:

- False alarms to avoid: f32 vector precision, merge loads that omit a property (#1278), and documented refusals under concurrent writes. This run's scripts supply every property, and they count `409` and optimize refusals as refusals.
- Gaps those runs listed: the other controls that take the export exclusion, cleanup during long reads (#958), served optimize resume over several tables, S3 faults during merges and schema apply, real embedding providers and the DST fleet.
- 40 commits merged since the last run. Most of the time went to the ones that can change answers without an error: the server now keeps cached traversal topology across writes and branch controls (#1363), a filter's later conditions run only on undecided rows (#1346), keyed upserts choose a route through the id index (#1318), a branch-held commit is looked up through a per-handle hint (#1184), writes carry over publications that changed no row (#1349), and an edge `@card` range widens in place (#1406).

This run found two new false alarms, both in its own new scripts. An unbound traversal has set semantics for endpoint pairs, so parallel edges give one row. A commit on a branch that was deleted or recreated, and never merged into main, is refused by id, as the branching guide says.

## Findings

No finding reached priority 0 or 1, so nothing was promoted to GitHub. All three stay in the findings queue.

| Queue slug | Finding | Priority |
|---|---|---|
| `og-stress-server-boot-refusal-keeps-lock` | A server that fails to start after it took the cluster lock exits 1 and leaves `__cluster/lock.json` naming its dead pid. A local root has no lease, so the next start fails with `state_lock_held` until `cluster force-unlock`. Seen for a tokens file with mode 666, a tokens file that does not parse, and a port in use. A settings refusal releases the lock (`release_settings_refusal`), but the token load, session settings and bind in `serve_with_mcp_settings` return with `?` and keep it. | 2 |
| `og-stress-load-csv-source-refusal-reports-unknown` | A direct `load csv` whose file lies inside the graph's own directory is refused at source admission with `effects: unknown`, `action: reconcile` and exit 2. Nothing was staged. A plain disallowed Blob URI answers `none`/`fix`. Related to #1413. | 2 |
| `og-stress-csv-output-null-equals-string-null` | `query --format csv` writes a null and the string `"null"` as the same bare `null`. Read back with `load csv`, a null becomes the string `"null"` and an empty string becomes null. | 3 |

The reproductions are [repros/server_boot_refusal_keeps_lock.sh](../../tools/stress/repros/server_boot_refusal_keeps_lock.sh) and [repros/csv_null_and_string_null.sh](../../tools/stress/repros/csv_null_and_string_null.sh). The queue entries hold the third reproduction as steps.

New evidence went to an existing issue as a comment: [#1355](https://github.com/ModernRelay/omnigraph/issues/1355#issuecomment-6932502060). A recorded optimize was accepted with `202` and then ended `failed` for `stream_export_slots` while an export ran.
