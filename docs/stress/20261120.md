## Lessons from earlier runs

From the queue's memories and the earlier runs:

- The last runs left these gaps: column-patch updates on served graphs and with BTREE or full-text indexes on the patched column, S3 faults during served optimize, a served apply killed after its graph started on a local root, and real embedding providers. This run took the first two.
- Main changed the code of several journeys since the last run: node removal reads its edges in bounded chunks (#1444), a traversal step streams its edge probe (#1460), `index build` builds BTREE indexes concurrently (#1395), and optimize reports table failures (#1418). Each got a new script.
- False alarms to avoid: set semantics of an unbound traversal, refused reads of commits on deleted branches, f32 vector precision, loads that omit a property (#1278), documented `409` refusals, the single-writer-process boundary of cleanup.

This run found four more false alarms, all in its own scripts. The queue memory `mem-wf-stress-modernrelay-omnigraph-false-alarms` lists them:

- A load holds at most 8,192 entities per touched type, unkeyed edges included (documented in the mutation guide, "Limits and conflicts").
- An overwrite load replaces only the types present in the batch. A type whose lines all filter away is absent and stays unchanged.
- Merge conflicts are entity-level. Both sides that change different properties of one row give `divergent_update` (merge guide, "Conflicts").
- The served operation record keeps the 32 newest terminal operations. An older id answers `lookup: unknown` by design (recorded-operations guide). `s3fault.py` now judges only the retained window.

## Findings

| Queue slug | Finding | Priority | GitHub |
|---|---|---|---|
| `og-stress-promoted-property-history-read-internal` | After `schema apply` makes a nullable property required, every read of that property at a commit before the promotion fails with code `internal`: "stored node:P.b has Int32, nullable true; declared Int32, nullable false". It fails when the old commit stored no null, for a whole-node `return { $p }`, and for an edge property. The docs say a promotion keeps retained commits and that a property reads where the commit stores it under its current name. #721 asked for exactly this. Cause: `check_stored_fields` in `crates/omnigraph/src/engine/typed_value.rs` requires equal nullability for historical versions too | 1 | [#1493](https://github.com/ModernRelay/omnigraph/issues/1493) |
| `og-stress-missing-graph-write-reports-unknown` | A direct `load`, `mutate`, `branch create` or `schema apply` against a path with no graph answers `outcome_unknown`, `effects: unknown`, `action: reconcile`, exit 2, though nothing was written. The troubleshooting guide says an error before a write submitted anything is `effects: none`. Cause: `open_writable` in `crates/omnigraph-cli/src/admission.rs` marks `writable_open` before the stamp read that fails | 2 | queue only |
| `og-stress-orphan-refusal-names-internal-column` | A load refused for an orphan edge says `__src 'a' not found in P`, naming neither the edge type nor the edge id. For an overwrite of a node type whose batch holds no edge, the refused edge is a retained committed edge, and the message does not say so | 3 | queue only |

The reproductions are [repros/promoted_property_history_read.sh](../../tools/stress/repros/promoted_property_history_read.sh) and [repros/missing_graph_write_reports_unknown.sh](../../tools/stress/repros/missing_graph_write_reports_unknown.sh).

## Journeys covered

Init a graph; evolve a schema (add, rename a property, a node type and an edge type, drop, re-add, make required, enum widening, index additions); append, merge and overwrite loads; filtered, traversal, bounded-hop, count and full-text queries; updates that patch columns; delete queries with cascades; branch create, merge with and without conflicts; historical reads by commit id; change feed polls across a promotion; `index build`, `optimize` and `cleanup`; a served graph over HTTP with bearer tokens and recorded optimize; an S3 cluster root under faults with restarts; upgrade from v0.16.0.

Not covered: a served apply killed after its graph started on a local root, real embedding providers, and column-patch updates beside concurrent writers on a served graph.
