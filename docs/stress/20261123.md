## Lessons from earlier runs

From the queue's memories and the earlier runs:

- The last runs left these gaps: a served apply killed after its graph started on a local root, real embedding providers, and column-patch updates beside concurrent writers on a served graph. None of them was taken: the largest change on main since the last run is #1504, which moves every branch into `main`'s catalog and adds storage format 18 with an upgrade from 17. Its code paths (branch create, delete, merge, the upgrade, cleanup of retired branches) had no coverage from earlier runs, so this run spent its time there, and on #1516 (S3 object keys).
- False alarms to avoid, from `mem-wf-stress-modernrelay-omnigraph-false-alarms`: set semantics of an unbound traversal, refused reads of commits on deleted branches, documented `409` refusals under load, the single-writer-process boundary of branch create, delete and cleanup.
- The box notes held: `/tmp` was empty after a restart, the harness came from the newest `stress/` branch, and RustFS came from its release.

This run found three more false alarms, all in its own scripts:

- After a branch is merged into `main`, deleted and created again under the same name from `main`, the new life holds the rows of the earlier life. A model must count a branch's own rows by its life, not by its name.
- `cleanup` without `--confirm` is a documented preview: it exits 0 and writes nothing to stdout, even with `--json`. Two scripts called it without `--confirm` and so never cleaned up.
- After `cleanup --keep 1`, a retired life of a name keeps its `__manifest` tree while a live branch was forked from that life. The docs say cleanup keeps data other branches still need.

`tfuzz.py` needed `--as act-a` on its direct load: a direct write to a cluster graph with a policy is denied without an actor (documented).

## Findings

| Queue slug | Finding | Priority | GitHub |
|---|---|---|---|
| `og-stress-s3-root-encoded-prefix-splits-keys` | On an `s3://` cluster root whose prefix holds a space, a non-ASCII letter, braces or a percent escape, `cluster apply` writes `__cluster/` under the percent-encoded spelling (`my%20data/`) and the graph's tables under the decoded one (`my data/`). Serving works. Removing the graph answers `complete` and deletes nothing, and declaring it again is refused with `deployment_outcome_unknown`, leaving the deployment outstanding. A root `.../a%41b/root` puts its graphs where a root `.../aAb/root` puts its own. v0.16.0 does the same. Cause: `s3_object_key` in `crates/omnigraph-storage/src/lib.rs` keeps `url.path()` percent-encoded while Lance decodes it. #1522 fixes the same split for shallow-clone roots only | 1 | [#1527](https://github.com/ModernRelay/omnigraph/issues/1527) |
| `og-stress-merge-refused-by-branch-create` | A merge into `main` is refused with `409 conflict` (`write authority 'branch_merge_input_capture'` or `'branch_merge_target:main' changed during preparation`, `effects: none`) whenever another client creates or deletes an unrelated branch during it. With three clients only creating and deleting branches, 59 of 60 merges were refused on main; the v0.16.0 server merged all 60. Since #1504 every branch create and delete publishes on `main`, and a merge, unlike a mutation or load, does not prepare again (`db/reprepare.rs`). The contract lists no `merge+branch` refusal | 2 | queue only |
| `og-stress-branch-name-refusal-names-native-ref` | A branch name with a space or one of `^ ? # ~ %` is refused with Lance's message, which names the internal native ref (`'sp ace.01M855A9GCQ1QAJMNA878AB2BW'`). The branch-name section of the docs does not state that rule. v0.16.0 does the same | 3 | queue only |

The reproductions are [repros/s3_root_encoded_prefix_removal.sh](../../tools/stress/repros/s3_root_encoded_prefix_removal.sh) and [mcont.py](../../tools/stress/mcont.py).
